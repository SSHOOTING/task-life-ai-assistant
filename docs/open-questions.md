## 二、没有异议就采用默认口径

| 编号 | 问题 | 默认口径 |
|---|---|---|
| Q-06 | H5 用户身份如何识别 | 服务端一次性令牌 + 短期会话；链接默认不可转发，有效期由服务端配置 |
| Q-07 | “提醒已送达”如何定义 | 只承诺尽力发送；记录待发送、已发送、失败、已过期，不声称用户一定看到 |
| Q-08 | 单条输入最多几次 LLM 调用 | 最多一次解析调用；主模型失败后的备用模型 fallback 视为同一次解析链路 |
| Q-09 | 解析模型和教练模型是否分开 | 允许分开配置，双方只依赖 OpenAI 兼容接口 |
| Q-10 | LLM 费用由谁承担、是否有上限 | 单条输入设调用上限；试用设总预算，超过后停止真实模型调用并回到 Mock |
| Q-11 | 是否保存解析证据和首次判断 | 保存 `parse_result_json`，用于回溯和错误归因，不向普通用户展示 |
| Q-12 | “论文开头改了”是否自动完成整项任务 | 不自动完成，只写 `task_progress(active)`；整项状态只能由用户明确修改 |
| Q-13 | 撤销、删除和“这句别记”的区别 | 撤销保留原话和历史；“这句别记”明确清除内容；备份按配置期限清理 |
| Q-14 | “一次输入、零回复、零点击”是否为硬指标 | 高置信场景作为硬指标；低置信允许一次合并澄清，不逐条追问 |
| Q-15 | 日期或时间没有证据时怎么处理 | 一律留空或进入待确认，不猜测、不默认成今天 |
| Q-16 | 谁判定验收结果 | 固定回归、主用例证据和真实盲测共同判定；任何单一方都不能单独宣布通过 |

如果你不同意某个默认口径，请在回复模板的“其他默认项”里写出编号和新口径。

## 三、请补充或确认的验收 case

确认上述口径后，请至少补齐以下 case 的可观察结果：

1. 一句话同时包含打卡、任务进展和生活感受；
2. 同一句话里包含两个任务或多个生活片段；
3. “准备背单词”与“背完单词”的区别；
4. “论文开头改了”与“论文完成”的区别；
5. 时间缺失、时间已过、日期歧义；
6. 条件动作，例如“如果初审通过就……”；
7. 重复微信消息和重复点击；
8. 解析超时、空结果、非法 JSON；
9. 用户只回答部分澄清问题；
10. 用户撤销一条记录但要求保留原话；
11. 用户说“这句别记”；
12. 用户 A 和用户 B 的数据隔离；
13. H5 身份令牌过期或链接失效；
14. 教练 Agent 失败但固定回执仍返回；
15. 提醒发送失败或额度不足。

## 四、确认后的动作

```mermaid
flowchart LR
    A[组长回答 Q-01 到 Q-05] --> B[冻结 MVP 范围和数据口径]
    B --> C[更新 SPEC 待决区和验收表]
    C --> D[把 TC-002 到 TC-014 变成可执行 case]
    D --> E[A/B/C 在 feature 分支实现]
    E --> F[契约测试和固定回归通过]
    F --> G[发布负责人统一部署蓝 PC]
```

在组长回复前，团队只做阅读、问题记录和契约准备，不按猜测修改业务逻辑。
